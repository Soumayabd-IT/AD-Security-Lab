# Kerberos

## Role in Active Directory
Default authentication protocol in AD since Windows 2000. It allows a user to prove their identity and access services without ever sending their password over the network, using a system of encrypted, time-limited tickets.

## Key definitions
- **KDC (Key Distribution Center)**: service running on the domain controller that combines the AS and the TGS, responsible for issuing all tickets.
- **krbtgt**: system account whose password hash encrypts and signs every TGT issued in the domain.
- **SPN (Service Principal Name)**: unique identifier for a service, used to request a ticket for a specific service.
- **Session key**: temporary symmetric key, generated by the KDC, shared between the two parties of an exchange to secure their communication.

## How it works

     
  ![Flux d'authentification Kerberos](images/kerberos_authentication_flow.svg)

  
1. **Pre-authentication** — the client encrypts a timestamp with its NTLM hash to prove it knows the password.
2. **AS-REQ → AS-REP** — the client requests a TGT (Ticket Granting Ticket) from the AS; the KDC replies with a TGT encrypted with the krbtgt key, containing a session key and an expiration time.
3. **TGS-REQ → TGS-REP** — the client presents its TGT + the SPN of the desired service to the TGS; it receives a service ticket (TGS) encrypted with the service account's hash.
4. **AP-REQ → AP-REP** — the client presents the TGS directly to the service, which decrypts it with its own hash to grant access (AP-REP optional, for mutual authentication).

## Exploited weaknesses
- Missing pre-authentication → [`attacks/03-kerberos-attacks/asrep-roasting.md`](../../attacks/03-kerberos-attacks/asrep-roasting.md)
- TGS encrypted with the service account's hash, retrievable by any authenticated user via a SPN → [`attacks/03-kerberos-attacks/kerberoasting.md`](../../attacks/03-kerberos-attacks/kerberoasting.md)
- Absolute trust the KDC places in a presented TGT → if the krbtgt hash is compromised, tickets can be forged → [`attacks/03-kerberos-attacks/golden-ticket.md`](../../attacks/03-kerberos-attacks/golden-ticket.md)
- Trust placed in a forged service ticket → [`attacks/03-kerberos-attacks/silver-ticket.md`](../../attacks/03-kerberos-attacks/silver-ticket.md)
- Abuse of delegation mechanisms (unconstrained/constrained/RBCD) → [`attacks/03-kerberos-attacks/delegation-abuse.md`](../../attacks/03-kerberos-attacks/delegation-abuse.md)

## Defensive takeaways
- Monitor for bulk TGS requests against high-value SPNs (Kerberoasting signature)
- Enable pre-authentication on all accounts
- Rotate the krbtgt password regularly (twice, because of password history)
